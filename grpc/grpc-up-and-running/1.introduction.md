- 동기식 요청 - 응답
- 비동기적(이벤트 기반)

REST API
대표적인 동기식 요청-응답 방식. http 기반의 네트워크 호출을 통해 구성.
많은 경우 프로세스 간 통신을 구축할 때 부피가 크고 비효율적이며 에러가 쉽게 발생한다.
효율적이고 확장성이 높은 느슨하게 결합되는 프로세스간 통신 기술의 필요성이 생김

grpc는 주로 동기식 요청-응답 스타일을 사용하지만, 초기 통신이 설정되면 완전 비동기식이거나 스트리밍 모드에서 작동할 수 있다
로컬 함수를 호출하듯 분산된 이기종 애플리케이션을 연결, 호출, 운영, 디버깅할 수 있는 프로세스 간 통신 기술이다.

grpc를 이용하여 애플리케이션을 개발할 때는 주로 서비스 인트페이스를 먼저 정의한다.
서비스를 사용하는 방법, 원격으로 호출되는 메서드 종류, 메서드를 호출하기 위한 파라미터, 메시지 형식 등을 포함한다.
서비스 정의에 사용되는 언어를 인터페이스 정의 언어(Interface Definition Language, IDL)라고 한다.
