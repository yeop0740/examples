# S2. Bidirectional Streaming

## 분류

별도 분류 케이스

## 별도 분리 이유

양방향 스트리밍은 fetch 작업이라기보다 지속 세션과 상호작용 모델의 비교에 가깝다. 단순 조회 성능보다 세션 운영 모델과 flow control 영향이 크다.

## 목적

연속적인 request/response 교환이 필요한 세션형 시나리오에서 별도 성능 특성을 측정한다.

## 적용 대상

- 대화형 세션
- 데이터 스트림 동기화
- 지속 연결 기반 상호작용

## 주요 변수

| 항목 | 값 |
| --- | --- |
| session 수 | `10`, `100`, `1000` |
| 메시지 빈도 | low, medium, high |
| 메시지 크기 | `1KB`, `10KB`, `100KB` |

## 설계 포인트

- fetch 문서 본류와 분리한다.
- 세션 지속 시간과 stream reset 비용을 반드시 기록한다.
- 클라이언트와 서버의 flow control 설정을 고정한다.

## 수집 지표

- session당 처리량
- 메시지 지연
- 세션 유지 비용
- stream reset/error 비율

## 수행 시점

- 지속 세션 기반 API 검토가 필요할 때만 수행
