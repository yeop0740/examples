# S5. Resume / Partial Retry Download

## 분류

별도 분류 케이스

## 별도 분리 이유

이 케이스는 정상 경로 fetch 효율보다 장애 복구 전략과 부분 재시도 방식 비교에 가깝다. 안정성 설계 성격이 강하므로 별도 라운드로 보는 편이 맞다.

## 목적

대용량 fetch 중 일부 chunk 실패가 발생했을 때 재시도와 resume 비용을 비교한다.

## 적용 대상

- 대용량 파일 다운로드
- 불안정 네트워크 환경
- 중간 실패 후 이어받기 요구가 있는 작업

## 주요 변수

| 항목 | 값 |
| --- | --- |
| 파일 크기 | `100MB`, `1GB`, `5GB` |
| 실패 지점 | early, mid, late |
| retry 범위 | full retry, partial retry |
| 네트워크 상태 | stable, lossy |

## 설계 포인트

- 부분 실패를 인위적으로 주입한다.
- resume offset 또는 chunk 재요청 방식을 명시한다.
- 정상 완료 시간보다 복구 완료 시간과 추가 비용을 더 중점적으로 본다.

## 수집 지표

- 복구 완료 시간
- 추가 전송 바이트
- 재시도 횟수
- 실패 후 성공률

## 수행 시점

- 운영 안정성 또는 재시도 전략을 결정할 때 수행
