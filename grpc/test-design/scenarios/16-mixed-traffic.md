# 16. Mixed Traffic

## 목적

단일 패턴이 아니라 여러 유형의 요청이 섞인 실제형 워크로드에서 체감 성능 차이를 확인한다.

## 시나리오 개요

- 작은 요청, 큰 응답, 헤더가 많은 요청, 중간 크기 요청을 함께 섞는다.
- 실제 서비스 트래픽 분포에 가까운 workload를 구성한다.

## 고정 조건

- 동일한 총 트래픽 비율 사용
- 동일한 서버 자원과 네트워크 조건 유지
- 요청 분포는 실험 내내 고정

## 주요 변수

| 항목 | 값 |
| --- | --- |
| 트래픽 조합 A | small `70%`, header-heavy `20%`, large-response `10%` |
| 트래픽 조합 B | small `50%`, write-heavy `30%`, large-request `20%` |
| 동시 client 수 | `100`, `500`, `2000` |
| 목표 부하 | `500`, `2000`, `5000 RPS` |

## 실행 절차

1. 앞선 개별 시나리오에서 사용한 payload를 재사용해 mix를 만든다.
2. 트래픽 조합별로 10분 이상 장시간 측정한다.
3. 요청 유형별 latency 분포와 전체 latency 분포를 모두 기록한다.
4. 필요하면 시간대별 burst를 섞은 변형 시나리오도 추가한다.

## 수집 지표

- 전체 평균 latency, `p95`, `p99`
- 요청 유형별 latency
- 전체 RPS와 유형별 RPS
- CPU / Memory 사용량
- 에러율

## 기대 관찰 포인트

- 단일 API에서는 차이가 작아도 mixed traffic에서는 scheduler, queue, serialization 특성이 누적되어 차이가 커질 수 있다.
- 작은 요청이 큰 요청에 의해 얼마나 영향을 받는지, 즉 noisy neighbor 현상을 확인하기 좋다.

## 주의사항

- 실제 서비스 분포를 모르면 의미가 약해지므로 가능한 한 운영 로그를 참고해 비율을 정한다.
- 결과 해석 시 전체 평균보다 요청 유형별 분해 결과가 더 중요하다.
